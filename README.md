# BizPilot

[![Validate](https://github.com/zeter1/BizPilot/actions/workflows/validate.yml/badge.svg)](https://github.com/zeter1/BizPilot/actions/workflows/validate.yml)

**BizPilot** — браузерное рабочее пространство для малого бизнеса. Проект объединяет заказы, клиентов, продажи и сделки, счета, финансы, денежный поток, услуги, заметки, календарь, уведомления и аналитику в одном интерфейсе.

Текущая версия интерфейса: **17.0**.

## Возможности

- обзор ключевых показателей бизнеса;
- заказы со статусами, сроками, суммами, себестоимостью и учётом времени;
- база клиентов и контактных данных;
- воронка продаж и работа со сделками;
- счета и контроль ожидаемых оплат;
- доходы, расходы и денежный поток;
- каталог услуг;
- блокноты и заметки с экспортом в Markdown;
- календарь, напоминания и центр уведомлений;
- аналитика и встроенные подсчёты;
- учебный демо-режим, изолированный от рабочей области;
- экспорт всех данных в ZIP и восстановление из резервной копии.

## Как устроено хранение данных

BizPilot работает без серверной базы данных: рабочие данные сохраняются локально в браузере через `localStorage`. Для переноса или резервного копирования предусмотрен встроенный экспорт ZIP и обратный импорт.

> Важно: очистка данных сайта/браузера может удалить локальную рабочую область. Для важных данных регулярно сохраняйте ZIP-копии средствами BizPilot.

## Требования

Для запуска достаточно современного браузера с поддержкой JavaScript, `localStorage`, `Blob` и стандартных Web API.

Дополнительный backend, Node.js и установка зависимостей для обычного использования не требуются.

## Запуск

### Вариант 1 — открыть напрямую

Откройте `index.html` в браузере.

### Вариант 2 — локальный HTTP-сервер

Для разработки удобнее запускать проект через простой локальный сервер:

```bash
python -m http.server 8000
```

После этого откройте:

```text
http://localhost:8000
```

## Использование

1. Откройте BizPilot.
2. Заполните данные бизнеса и профиль владельца в настройках.
3. Добавьте клиентов, услуги, сделки, заказы и счета.
4. Ведите доходы/расходы и контролируйте денежный поток.
5. Используйте календарь, заметки и уведомления для текущей работы.
6. Периодически открывайте раздел «Ваши данные» и сохраняйте ZIP-резервную копию.
7. Для знакомства с возможностями можно включить учебный демо-режим — рабочие данные перед этим сохраняются отдельно в браузере.

## Структура проекта

```text
BizPilot/
├── index.html       # интерфейс и разметка приложения
├── css/
│   └── styles.css   # стили, адаптивность и темы
└── js/
    └── app.js       # состояние, бизнес-логика, хранение и UI-поведение
```

Приложение намеренно собрано как статический frontend без сборщика и внешнего package manager.

## Резервные копии

Экспорт BizPilot создаёт ZIP-архив с данными рабочей области. Импорт проверяет формат архива и позволяет восстановить сохранённое состояние.

Перед очисткой браузера, переносом на другой компьютер или крупными изменениями данных рекомендуется скачать свежую резервную копию.

## Проверка и CI

Репозиторий содержит GitHub Actions workflow [`.github/workflows/validate.yml`](.github/workflows/validate.yml). На изменениях приложения он автоматически проверяет:

- синтаксис `js/app.js` через `node --check`;
- что локальные CSS/JS-ресурсы, на которые ссылается `index.html`, существуют;
- что приложение и ключевые статические ресурсы отдаются локальным HTTP-сервером;
- diff hygiene через `git diff --check`.

Локальная быстрая проверка JavaScript:

```bash
node --check js/app.js
```

После функциональных изменений дополнительно нужен browser runtime smoke test: создание/редактирование сущностей, переключение разделов, сохранение после reload, demo-mode, ZIP export/import. Полный browser E2E сейчас **NOT VERIFIED** автоматическим CI.

## Ограничения

- данные по умолчанию привязаны к конкретному браузеру и профилю пользователя;
- серверной синхронизации и многопользовательской работы в текущей архитектуре нет;
- удаление локального хранилища браузера без резервной копии может привести к потере данных;
- полноценное runtime-тестирование всех пользовательских сценариев должно выполняться в браузере.

## Безопасность данных

Не публикуйте экспортированные резервные копии, если в них есть реальные клиентские, финансовые, контактные или банковские данные. Перед отправкой диагностических материалов третьим лицам удаляйте персональные и конфиденциальные сведения.

Политика ответственного сообщения об уязвимостях: **[SECURITY.md](SECURITY.md)**.
